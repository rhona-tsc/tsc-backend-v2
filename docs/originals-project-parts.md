# Add and remove project parts

Owners and authorised TSC managers can use **Parts we are building → Owner tools: add or remove parts** in the workspace. A custom name such as Click track, Percussion or Saxophone is accepted; a project can contain up to 30 distinct parts. Whitespace is normalised and duplicates are checked without case sensitivity. Mixing and mastering retain their existing separate stages.

New parts are appended to the plan for future rounds. They appear immediately in the parts list, advance reservations, recommendations, planned royalty illustration and next-instrument selector after the workspace refreshes. They do not change the current round, start a clock, send invitations, or create accepted contributions or royalty shares. A new recording role participates in the normal contributor pool if its submission is accepted. A reference click-track file can still be uploaded using its existing file type.

Unused planned parts can be removed. A current-round part, an active or submitted recording place, a waiting advance place, an active current-round invitation, or submitted/accepted/disputed material blocks removal and displays the reason. The last part and, before publication, the last required foundation part are protected. Move to the next stage before removing an unused current-round part. Contributors can release their advance places through the existing flow. Rejected, withdrawn or retracted history is retained; files and agreement evidence are never deleted by a plan edit.

Edits are available during draft/changes-requested/planning/recording/owner-review states. They are blocked during moderation, production, final credits and completed/paused/closed states, or if a credit version already exists. Formal credit versions and accepted shares are never rewritten by this endpoint. Old rounds containing removed parts cannot be implicitly reopened; add the part back explicitly if it is required again.

`POST /projects/:id/roles` takes `{action: 'add' | 'remove', roleName}` under the existing authenticated private-preview and participation checks, followed by an explicit owner/TSC management check. Server-side removal rules are recalculated from current participation records. Updates compare the role plan, project stage, current round, credit version and Mongoose version before writing, rejecting stale owner tabs. New advance holds increment the same plan version only while the role and stage still match; a role removal that wins first causes the new hold to be cancelled instead of leaving an orphan reservation. Events record the actor and before/after plans. No schema migration or new collection is required.

Participant view and the owner's read-only participant preview do not display edit controls. Existing reference uploads, recordings, reservations and royalty calculations keep their original behaviour.
