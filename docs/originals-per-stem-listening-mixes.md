# Listening mixes for individual submitted stems

Each new submission contains one to three independently reviewable takes. Each take contains one isolated stem and its own listening mix of that stem with the existing authorised project track or approved stems, where available. The contributor's other submitted alternatives are excluded from that listening mix. For three stem options, upload three corresponding listening mixes. MP3 is recommended for review, while the isolated recording remains the source used in the final mix.

The submission form pairs each selected stem with a distinct uploaded listening mix. Missing, hidden, wrong-kind or other-reservation files cannot enable submission. Labels use the stem filenames (within the existing 80-character limit) so the owner can match the preview to the approval dropdown. Optional effects references attach to the first selected stem, remain explicitly labelled as references and still count towards the three-stem limit.

Owner review includes a separate embedded listening preview for each option. Secure playback links are requested only when its preview is opened. Existing whole-take or range selection chooses the corresponding isolated stem; review mixes are not added to the approved project layers. Multiple options in one role do not create extra royalty shares.

The existing backend already accepts up to three takes, each with a stem and mixdown, so no schema migration or modification of existing submissions is required. Legacy grouped takes remain readable and retain their existing selection semantics. The replacement workflow continues to accept a replacement stem and matching mix, rather than reinterpreting an old grouped record. Original uploads remain intact.

Round-open email guidance matches this workflow. Contributor agreement version 0.4 updates the deliverables paragraph and retains the existing consent/version/hash checks. Mix/master agreements are unchanged. Previous acceptance text/hash evidence and existing timed reservations are not rewritten. Outdated waiting contributors use the existing explicit renewal flow.

Validation covers three independent pairs, incomplete/reused/unavailable mix selections, optional effects, server file ownership and pairing, embedded playback, selection of the second option, and mobile layout. All fixtures are local; no production files, emails or contracts are created.
